# Project Status

## Overview
The project is a Sales Analysis Dashboard built in Python using Streamlit. It loads data from a local CSV file, allows filtering by region and category, and presents various Key Performance Indicators (KPIs) and visualizations using Plotly.

**Tech Stack:**
- Python
- Streamlit (Web Framework)
- Pandas (Data Manipulation)
- Plotly Express (Data Visualization)

**Main Entry Points:**
- `app.py`: The main Streamlit application file.
- (Unused) `src/sales_analysis_dashboard/__init__.py`: Contains a CLI entry point `main()` defined in `pyproject.toml`, but typically unused for Streamlit.

## Architecture
- `app.py`: Contains the entire frontend and backend logic. Handles data loading, filtering, metric calculation, and chart rendering.
- `requirements.txt` & `pyproject.toml`: Dependency management files.
- `src/sales_analysis_dashboard/`: Appears to be a boilerplate python package structure, likely generated by a tool like `uv`, but largely unused.
- `superstore.csv`: The primary data source.

## Data Sources
- **Source:** Local CSV file named `superstore.csv`.
- **Transformation:**
  - Read with `latin1` encoding.
  - Column names are stripped of whitespace.
  - `Order Date` is converted to datetime objects using `dayfirst=True`.
  - Filtered dynamically based on sidebar selections (Region, Category).
  - Aggregated dynamically for visualizations (e.g., grouped by month, sub-category, state).

## Known Issues

### Critical
- **Logic Error in KPI Calculation:** [RESOLVED] In `app.py` (Line 56 & 69), `total_orders = len(filtered_df)` calculates the total number of rows (line items), not unique orders. It should likely be `filtered_df["Order ID"].nunique()` if an `Order ID` column exists.
- **Dependency Misalignment:** [RESOLVED] `requirements.txt` and `pyproject.toml` define different dependencies. `requirements.txt` is missing `plotly`, while `pyproject.toml` includes `scikit-learn` (unused) and is missing `pandas`. `README.md` instructs to use `requirements.txt`, which will fail because `plotly` is missing.
- **Date Parsing Risk:** [RESOLVED - False alarm, verified data is DD/MM/YYYY] In `app.py` (Line 18), `pd.to_datetime(..., dayfirst=True)` is used. Superstore datasets commonly use US date formats (`MM/DD/YYYY`). `dayfirst=True` might parse dates incorrectly if the raw data is in US format.

### Moderate
- **Hardcoded File Path:** [RESOLVED] `app.py` (Line 15) hardcodes the data file path `"superstore.csv"`. This should ideally be configurable via environment variables, or a file uploader widget should be provided in the UI.
- **Missing Core Column Feedback:** [RESOLVED] `app.py` has checks like `if "Sales" in filtered_df.columns:`, but if the column is missing, the metric or chart is simply omitted without notifying the user why it's missing. Added clear warnings for all KPIs and charts.
- **Inconsistent Documentation:** [RESOLVED] `README.md` states the dataset is `sales_data.csv`, but `app.py` expects `superstore.csv`.

### Minor
- **Unused Code:** `src/sales_analysis_dashboard/__init__.py` contains a `main()` function which is unnecessary for a Streamlit app.
- **Monolithic Structure:** All logic (data loading, filtering, layout, charts) is contained within a single `app.py` file.
